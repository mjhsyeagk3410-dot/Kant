## 11월 12일 목요일 수업 복기 
### docker에 대해 알아보자 
#### 왜 쓰는가
```md
그동안은 내 컴퓨터(로컬 환경)에서만 파이썬 코드가 잘 돌아가도록 세팅했다면, 이제부터는 내 컴퓨터가 아니라 팀원 컴퓨터에서도 1초만에 똑같이 실행되는 환경을 만들어줄 수 있게 된다. 
```
#### Docker CLI
```sh
# docker 명령어를 치기 전에, 윈도우라면 docker desktop이 켜져있는지 먼저 확인해야함.

# 버전확인
docker --version

# 이미지 목록 확인
docker images 

# 이미지 다운로드
docker pull hello-world # hello-world는 이미지명입니다

# 컨테이너 생성 및 실행
docker run hello-world 

# 이미지 지울때 
docker rmi hello-world

# 실행되고있는 컨테이너 보는법 
docker ps

# 중단된 컨테이너도 보는법
docker ps -a

# 실행중인 컨테이너 멈추는법
docker stop hello-world # 근데 hello-world는 딱 실행되고 바로 꺼지는 컨테이너라서 이런 작업이 필요없으며, 이 작업은 내가 멈추기 전까지 계속 돌아가는 컨테이너에만 해당된다 
# 이렇게 멈추고 다시 실행하고 싶으면 docker start hello-world라고 하면됨

# 실행중이거나 중단된 컨테이너 삭제하는법
docker rm hello-world
# 혹은
docker rm -f hello-world #묻지도 않고 강제로 삭제하겠다

# 리눅스 이미지를 받아 컨테이너 생성하기 
docker run -it --name my-server ubuntu:24.04 bash # pull로 받지 않고 바로 run을 해도, 이미지를 pull하는것부터 컨테이너 생성까지 바로 된다. 

# nginx라면
docker run -d --name my-webserver -p 8080:80 nginx

# mysql이라면
docker run -d --name my-sql -e MYSQL_ROOT_PASSWORD=admin1234 -p 3306:3306 mysql:8.4

# os, 웹서버와는 다르게 컨테이너 구동을 해줘야하는 경우도 있다. 그에 대한 방법. 
# 참고로 컨테이너 구동 방법은 애초에 이미지마다 다 다르다. 그래서 이미지 받아오는곳에서부터 구체적인 가이드가 있다. 
docker exec -it my-sql mysql -u root -p 
# 여기까지 쳐야 패스워드 입력창이 뜨고 치고 들어가면 mysql의 쿼리문을 칠 수 있는 입력창이 활성화가 되고 데이터베이스 확인이 가능하다 

# postgres라면
docker run -d --name my-pg -e POSTGRES_PASSWORD=1234 -p 5432:5432 postgres:18
# 여기도 비밀번호를 입력해야하기 때문에, exec로 구동하는 위의 작업이 필요하다. (postgres도 sql임)
```

## 11월 13일 금요일 수업 복기 
### SQL과 쿼리문? 
- SQL
```md
Structured Query Language(구조적 질의 언어)로써 관계형 데이터베이스(MySQL, Oracle, PostgreSQL 등)에 있는 데이터를 관리, 조작하기 위해 사용하는 표준 프로그래밍 언어
```
- 쿼리문(SQL Query)
```md
SQL 언어를 이용해 데이터베이스에 실제로 내리는 '명령문(질의)를 뜻함. "데이터베이스에 무엇을 하라"고 요청하는 구체적인 코드 한 줄 또는 블록. 
```
#### SQL테이블 만들기 (vs code에서)
```sh
## sql파일 만들고싶을때 kant_shop.sql 이렇게 만든다
## 쿼리문에서는 지금 앞에 ##라고 붙인것을 -- 이렇게 쳐야 주석처리 된다. 그리고 쿼리문에는 순수하게 쿼리문만으로 작성이 되어야 하기때문에 #같은게 하나라도 들어가면 에러가 난다. 

## 1. 데이터베이스 생성
CREATE DATABASE kant_shop;
# 세미콜론은 오타가 아니다 쿼리문에서는 콜론이 아닌 세미콜론이 찍힌다 
# 데이터베이스 생성과 밑에 테이블 생성하는것 구분짓기

## 2. 새로 만든 데이터베이스에 접속 (특정 DB를 사용)
\c kant_shop
# \c : 지금부터 작업할 데이터베이스를 지정(연결)한다

## 3. 상품 테이블 생성
CREATE TABLE product (
    id SERIAL PRIMARY KEY, #primary key는 각 상품을 고유하게 식별하는 기본키, serial은 데이터를 추가할때마다 번호가 1씩 자동 증가되는 기능
    name VARCHAR(100) NOT NULL, #VARCHAR(100)은 최대 100글자까지 저장할 수 있는 가변길이 문자열을 사용한다는 뜻, NOT NULL은 이름이 없는 상품은 등록되지 않도록 강제한것
    price INT NOT NULL, # INT는 정수형으로 처리하겠다는 의미이며, NOT NULL은 가격이 누락되지 않게 하기 위함
    stock INT NOT NULL # INT는 정수형으로 처리하겠다는 의미이며, NOT NULL로 재고 정보 입력이 필수임을 지정한것
);

```
### Docker Volume(볼륨)
#### 쓰는 이유
```md
컨테이너가 생성하고 사용하는 데이터를 컨테이너 내부가 아닌 호스트 컴퓨터의 특정 공간에 안전하게 저장하도록 돕는 기능. 보통 도커 컨테이너는 기본 일회성이므로 컨테이너가 삭제되고 재시작되면 그 안에 데이터도 전부 삭제되는데 볼륨은, "데이터는 컨테이너와 별개로 안전한곳에따로 보관하자"라는 개념이다. 
```
#### 볼륨관련 docker cli
```sh
# 볼륨 만들기 
docker volume create pgdata #pgdata는 내가 만들 볼륨의 이름이므로 여기는 임의 수정가능함 

# 생성된 볼륨의 상제 구성 정보와 저장위치 확인하기
docker volume inspect pgdata 

# 만든 볼륨을 기존 컨테이너에 연결할때 
docker run -d --name my-pg -e POSTGRES_PASSWORD=admin1234 -p 5432:5432 -v pgdata:/var/lib/postgresql postgres:18
# 볼륨을 사용한 흥적이 보이는가? -v 부터 쓴게 볼륨이고 이게 볼륨을 기존 컨테이너에 연결하는 방법이다. 
```
### Docker Compose(컴포즈)
#### 왜 쓰는가
```md
일단 위에 볼륨을 컨테이너에 추가할때만 보더라도 안그래도 길었던 커맨드가 볼륨을 연결하려고 하면 더 길어진다. 기본적으로 docker 명령어는 쓰기가 어렵다. 이럴때 쓰이는게 도커 컴포즈 업이라는 명령어이고, 이 명령어를 쓰기 위해서 이 컴포즈를 사용하기 위한 yml(야몰)파일을 만들어야한다. 

docker run은 수동으로 하나식 조립하는 망치,
docker compose는 설계도(야몰파일)를 보고 한번에 뚝딱 제품을 만들어주는 스마트팧 자동화 로봇이다. 
```
- yml파일은 compose.yaml 이렇게 만든다. 
```sh
services:                       # 실행할 컨테이너(서비스) 목록 - 필수
  서비스이름:                   # 예: db, web(직접 정하는 이름)
    image: 이미지: 태그         # 사용할 이미지
    container_name: 이름        # 컨테이너 이름 (생략 시 자동 생성)
    enviroment:                 # 환경 변수(-e)
      KEY: value
    ports:                      # 포트 연결(-p) - 문자열로 감싸는 것을 권장
      - "호스트: 컨테이너"
    volumes:                    # 사용할 볼륨 선언 (최상위)
      - 볼륨이름: 컨테이너 경로

volumes:
  볼륨이름: 
```
- 위의 양식을 왠만하면 복사 붙여넣기해서, 해당 값들만 바꿔주는걸 추천한다. 왜냐면 들여쓰기가 조금이라도 이상하면 이 야몰파일은 기능하지 못하기때문이다. 

```sh
services:               
  db:           
    image: postgres: 18 
    container_name: kant-pg
    enviroment:
      POSTGRES_PASSWORD: admin1234
    ports:  
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:
    external: true # 이건 왜? 위에 양식엔 없었는데? compose가 새로 만들지 말고 기존 pgdata 볼륨을 그대로 쓰라는것. 만약 이것을 쓰지 않으면? compose는 compose-lab_pgdata처럼 폴더명이 붙은 새 볼륨을 만든다 
```
#### 컴포즈를 쓰기위한 docker cli
```sh
docker compose up -d 
```
이 한 줄의 원본은 원래 이렇게 썼던것
```sh
docker run -d --name my-pg -e POSTGRES_PASSWORD=admin1234 -p 5432:5432 -v pgdata:/var/lib/postgresql postgres:18
```
뭐가 더 실수하지 않고 안전할지는 눈에 보기만 해도 알 수 있다. 

삭제할때는 
```sh
docker compose down
```
이렇게 쓴다.
