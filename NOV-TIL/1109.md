## 01 코드의 기능을 구현하려고 할 때 주석을 잘 달아주자
- 주석은 사람을 위한것이다. 
- 나 자신을위해서다. 여섯달 뒤에 이 코드를 볼 내가 "과거의 내가 대체 무슨 생각을 한 거지?" 하고 있을 미래의 나를 위한거라고 생각하자
- 뻔한 일을 다시 한 번 풀어쓰는 주석은 의미없다
- 좋은 주석은 '왜?'를 설명한다. 
- 어떤 제약 때문에, 어떤 우회책을 쓴이유, 코드만 봐서는 알수없는 어떤 결정같은것들을 쓰면 좋다. 
- 코드를 고쳤다면 주석도 고쳐야한다. 틀린 주석은 없는 주석보다 나쁘다. 
- 코드를 주석 처리한채 방치하지 말자. 필요 없으면 지우자. 어차피 버전관리가 기억한다.

## 02 enumerate()에 대해서 알아보자
### enumerate()
```md
개념설명: 
일단 파이썬 내장함수다. 
list 형식의 데이터를 다루는데, index를 자동으로 생성해주는 장점이 있다. 
이를 활용하면, 임의로 index를 만드는 수고를 덜 수 있고, 데이터의 총 크기를 확인하기 위해서 len()을 사용하지 않아도 괜찮다. 
```
출처: [준노트](https://m.blog.naver.com/rheesungjun/222753329608)

**튜터님이 코드에서 사용했던 예시**
```sh
# 가위바위보 게임만들때 (kant_study/01_python/rps_game)
# 승패 판결 목록 표시
def show_records(recodes):
    print("\n[판별 승패 목록]")
    # "1 판 : 가위 vs 바위 => 패배"
    # "2 판 : 가위 vs 바위 => 패배"
    # "3 판 : 가위 vs 바위 => 패배"
    for number, record in enumerate(recodes, start=1):
        print(f"{number}판: {record}")
```
**왜 이때 여기서 enumerate를 썼을까?**

## 04 상속, 부모클래스, 자식클래스에 대해서 알아보자
**개념 이해해보기**
```md
상속(Inheritance)은 물려주는 클래스(부모클래스)의 내용(속성과 메소드)을 물려받는 클래스(자식클래스)가 가지게 된다 

예를들어 국가라는 클래스가 있을때, 이걸 상속받은 한국, 일본 등의 클래스를 만들 수 있고, 국가라는 클래스의 기본적인 속성으로 인구라는 속성을 만들었다면, 상속 받은 한국, 일본 등의 클래스에서 부모 클래스의 속성과 메소드를 사용할 수 있다. 

자식클래스를 선언할때 소괄호로 부모클래스를 포함시킨다.   
자식클래스에서는 부모클래스의 속성과 메소드는 기재하지 않아도 포함된다. 
```
출처: [wikidocs](https://wikidocs.net/16073)   

**튜터님 코드예제1**
```sh
# 부모 클래스 Base Class, Super Class, Parent Class
class Animal:
    # 공통 기능 
    def breathe(self):
        print("숨을 쉽니다.")
    def sound(self):
        print("소리를 냅니다.")

# 상속 (Inheritance)
class Dog(Animal):
    # 상속받은 클래스에서만 있는 고유 기능 
    def bark(self):
        print("멍멍")

# 인스턴스 생성 
dog1 = Dog()
dog1.breathe() # 부모클래스로부터 물려받은 메서드를 그대로 사용할 수 있다
dog1.bark()    # 자식클래스의 고유기능 

# 메소드 오버라이팅(Method Overriding)
# 부모 클래스에서 정의된 메소드를 수정 또는 추가하는 기능(재정의)

class Cat(Animal):
    def sound(self):
        print("야옹") #재정의

nabi = Cat()
nabi.sound()
```
출력:
```md
숨을 쉽니다. 
멍멍
```

## 05 미니 프로젝트에 대한 고민하기
```md
1. 첫인상: "와..."
2. 첫번째 트라이: 그림판을 열어본다. "아 이걸론 힘들겠다" 포기. 
3. 두번째 트라이: 엑셀을 열어본다. "도구 사용의 한계를 느낌" 포기. 
4. 세번째 트라이: 옵시디언을 설치해본다. 구글링으로 옵시디언으로 전체적인 구조를 잡는법을 알아보다가 이것도 뭔가 지금 바로 하기엔 도구 사용이 어렵다라고 느껴졌다
5. 네번째 트라이: 종이에다가 그림판에서 하려고 했던것을 그려봤다. 네모칸 네개를 그리고 판매 상품, 메뉴, 할인쿠폰, 결제계산순서를 넣고 판매상품은 상품 1-5개와 가격과 재고여부가 있다라는것, 메뉴는 1부터 7까지 메뉴가 있으며 7번째는 종료를 한다는 의미로 알파벳 q. 할인쿠폰은 3가지. 를 그리고 써봤다.
```
