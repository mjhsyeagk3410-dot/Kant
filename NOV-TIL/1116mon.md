## 02 docker-compose.yaml 코드 뜯어보기 
```md
1. 프로젝트 이름 설정
> name: sportscenter
이 도커 컴포즈 프로젝트 전체의 이름을 sportscenter로 지정. 
도커가 실행될때 이 이름이 프로젝트그룹명으로 활용

2. 데이터베이스 서비스(services: db)
> container_name: sportscenter-db
실행되는 도커 컨테이너의 이름을 sportscenter-db로 명확하게 고정. 나중에 도커 명령어를 사용할때
이 이름으로 쉽게 제어할 수 있음 
> image: postgres:18
도커 허브에 있는 공식 PostgreSQL 18 버전 이미지를 다운로드 하여 데이터베이스의 기반으로 사용 
> environment: 
환경변수 설정, POSTGRES_PASSWORD: admin1234 데이터베이스 관리자 계정(postgres)의 비밀번호를 
admin1234로 지정. 나중에 DB에 접속할때 이 비밀번호를 입력해야 함. (별도의 유저 아이디를 지정하지 않아 
기본 관리자 계정명은  postgres가 된다)
> ports: - "5432:5432"
포트 연결. 내 컴퓨터(호스트)의 5432번 포트와 컨테이너 내부의 5432번 포트를 연결. 이 설정 덕분에 내 PC에
깔림 pc에 깔린 DBeaver, pgAdmin 혹은 개발 중인 프로그램에서 localhost:5432를 통해 데이터베이스에 자유롭게
접속할 수 있습니다. 

3. 볼륨 정의(volumes: pgdata:)
위에서 사용한 pgdata라는 이름의 저장소 공간이 실제로 시스템에 생성될 수 있도록 선언해주는 부분
```

## 03 sportscenter_study.sql 코드 뜯어보기
```md
1. 데이터베이스 생성(DDL)
> CREATE DATABASE sportscenter;
PostgreSQL이나 같은 DBMS에서 sportscenter 라는 이름의 새로운 데이터베이스(저장소)를 생성하는 명령어. 
앞으로 만들 모든 회원, 종목, 강좌, 사물함 테이블은 이 데이터베이스안에 저장됨 

2. 회원 테이블(members) 및 샘플 데이터
> member_id SERIAL PRIMARY KEY
회원의 고유 식별 번호(회원번호). SERIAL은 데이터가 추가될 때마다 번호가 자동으로 1씩 증가(Auto Increment)하게 설정하는 타입. PRIMARY KEY로 지정되어 중복될 수 없고 빈 값일 수 없는 핵심 키 역할

> name VARCHAR(30) NOT NULL
회원의 이름. 최대 30바이트 (글자 수 기준 넉넉함)까지 저장할 수 있으며 반드시 입력해야함(NOT NULL)

> gender CHAR(1) NOT NULL
성별을 나타냄. 'F'또는 'M'처럼 한 글자로 받기 위해 CHAR(1)을 사용했고 필수로 입력. 

> birth_year SMALLINT NOT NULL
출생연도. SMALLINT는 작은 정수형(약 -3만~3만)으로 연도를 저장하기에 충분하며 필수로 입력

> phone, email, region
연락처, 이메일, 거주지역. 
뒤에 NOT NULL이 없으므로 회원이 필수로 입력하지 않아도 되는 선택 항목

> join_date DATE NOT NULL
센터에 가입한 날짜를 날짜(DATE)타입으로 기록하며 필수 입력항목. 

> INSERT INTO members (...) VALUES ('김하늘', 'F', 1995, '010-1234-5678', 'ABCD@EMFG.COM', '마포구', '2026-09-01');
이거는 이제 2번테이블을 작성완료하면 그 안에 넣을 데이터를 입력하는 방식이다. 
member_id는 SERIAL에 의해 자동으로 1이 부여, 성별은 여성, 1995년생, 마포구 거주, 2026년 9월 1일 가입 데이터가 안전하게 저장된다. 

3. 종목 개설강좌 테이블(sports) 및 샘플 데이터
> CREATE TABLE sports
> (
>    sports_id   SERIAL      PRIMARY KEY,
>    sports_name VARCHAR(20) NOT NULL
> );
> INSERT INTO sports (sports_name) VALUES ('수영');
> INSERT INTO sports (sports_name) VALUES ('헬스');

- 스포츠 센터에서 다루는 대분류 운동 종목(수영, 헬스, 요가 등)을 관리하기 위한 테이블 
- sports_id는 종목 고유 번호(기본키), sports_name은 종목 이름
- 이후 INSERT문을 통해 1번: 수영, 2번: 헬스라는 두 가지 기본 종목 대분류를 미리 등록 

4. 개설 강좌 테이블(courses) 및 샘플 데이터
> sports_id INT ... REFERENCES sports
이 강좌가 어떤 종목에 속하는지 나타내는 외래키(FK). sports테이블의 sports_id를 참조하므로 등록하려는 종목이 반드시 sports 테이블에 존재해야함 
> capacity SMALLINT
정원인원
> fee INT 
수강료

> INSERT INTO courses (...) VALUES (1, '수영 초급 새벽반', '초급', '월수금', '06:00', 20, 70000);
첫번쨰 줄은 sports_id = 1(수영)을 참조하여 '수영 초급 새벽반'(월수금, 06:00 시작, 정원 20명, 수강료 7만원)강좌를 개설
> INSERT INTO courses (...) VALUES (2, '헬스 자유이용', '자유', '매일', '06:00', 50, 50000);
두번째 줄은 sports_id = 2(헬스)를 참조하여 '헬스 자유이용'(매일, 06시 시작, 정원 50명, 수강료 5만원)강좌를 개설 

5. 1:1 사물함 테이블(lockers) 및 샘플 데이터
> locker_no INT PRIMARY KEY
사물함 번호 그 자체를 기본키(PK)로 사용 (ex 101번 사물함, 102번사물함)
> member_id INT NOT NULL UNIQUE REFERENCES members ...:
- 어떤 회원이 이 사물장을 쓰는지 연결하는 외래키(FK)
- UNIQUE 제약 조건이 걸려 있어, 한 명의 회원이 여러 개의 사물함을 중복해서 가질 수 없고, 한 사물함은 한 사람만 쓸 수 있는 1:1 구조를 완벽히 보장 
> ON DELETE CASCADEE
만약 해당 회원이 탈퇴(DELETE FROM members)하면 그 회원이 쓰던 사물함 배정 정보도 자동으로 삭제되도록 안전장치를 걸어둔 것
> INSERT INTO lockers VALUES (101, 1, '2026-11-01');
101번 사물함을 회원번호 1번('김하늘')에게 2026년 11월 1일 자로 배정 
> INSERT INTO lockers VALUES (102, 3, '2026-11-01');
102번 사물함을 회원번호 3번에게 배정하려고 함 
```
