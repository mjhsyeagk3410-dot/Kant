### 터미널 기초
- **pwd** 로 현재 있는 폴더의 주소를 알려준다. OCT-TIL 폴더에 있다면, /kant/OCT-TIL 이런식으로. 
- **ls** 은 지금 폴더 안에 든 것을 보여준다. 지금 OCT-TIL 폴더에서 이 명령어를 치면, 261027.md  261028.md  261029.md  261030.md  261031.md  OCT_TIL.md 이렇게 나온다. 이때 점을 찍은 파일은 안보인다(.git같은) 이때는, ls -a를 친다. 그러면 숨겨진 파일도 볼 수 있다. 근데 이때는 대략만 보여준다면, 우리가 많이 썼던 ls -al을 쓰면, 자세하게 숨김파일까지 다 보여준다. 
- **mkdir** 은 새 폴더를 만든다. mk는 make의 약어이고, dir은 디렉토리이다. 현재 폴더라면, mkdir OCT-TIL 이렇게 만드는것. 
- **cd** 는 폴더 안으로 들어갈때 쓴다. cd ~ 를 쓰면 홈디렉토리로, cd kant를 쓰면 현재 이 폴더의 상위 디렉토리인 kant 폴더로, 그리고 이 폴더에 들어올때는 cd OCT-TIL을 쓴다. 
- **touch** 는 파일을 만들때 쓴다. touch 261031.md 이런식이다. 참고로 당연하게도 빈 파일이다. 
- **echo** 는 단독으로 쓸때는 글자를 띄웁니다. 하지만 글자를 적은 다음에, > 261031.md라고 쓰게 될 경우, 파일에 해당 글자를 작성합니다
- **cat** 은 그 파일의 내용을 불러와 출력하고 싶을때 씁니다. 만약 cat 261030.md라고 한다면, 제가 261030.md에 적은 TIL이 모두 터미널에 출력됩니다. 
- **mv** 는 파일을 다른 폴더에 옮길때 사용. 또한 파일의 이름을 바꾸고싶을때도 사용한다. 먼저 파일을 다른 폴더에 옮길때는 mv 261031.md OCT-TIL 이런식이다. 그리고 파일 이름을 변경할때는 mv 261031.md 261130.md 이런식이다. 
- **cp** 는 파일을 하나 더 복사하고싶을때 쓴다. cp kant/261031.md 261031완성파일.md 이런식이다.
- **rm** 은 파일을 지운다. 파일? 그러면 폴더를 지울때는? rm -r을 쓴다. rm -r OCT-TIL 이런식이다. 또, 묻지도 알리지도 않고 지우는 방법이 많이 썼던, rm -rf다. rm -rf OCT-TIL을 치면 OCT-TIL 폴더를 바로 지운다.  
#### 편한 단축키들 
- **Tab**은 이름을 자동 완성해준다. kant 폴더에서 OC만 치고 Tab을 누르면 OCT-TIL이 바로 모두 쳐진다. 
- **↑**은 방금 전 명령 다시 불러오기입니다. 현재 ↑를 한다면, rm -rf OCT-TIL 명령어가 나오겠고 또 ↑를 한다면, rm -r OCT-TIL이 나올겁니다
- **Ctrl+C**는 실행을 멈추는 기능과 치던 줄을 취소하는 단축키입니다. 간혹 터미널에서 명령어가 쳐지지 않을때 이 단축키를 쓰거나, 쓰다가 잘못쓴 명령어를 취소할때 씁니다. 

### Git 기본흐름
- Git에는 4개의 공간이 있다. 작업 폴더, 대기실, 내 저장소, 원격 저장소가 있다. 
- 이걸 이제 우리가 배운 단어로는 워킹 디렉터리, 스테이징에리어, 로컬 레포지토리, 리모트 레포지토리다. 
- 보통 워킹 디렉터리, 스테이징에리어, 로컬 레포지토리까지는 로컬 곧 우리 PC의 영역이고, 이제 리모트 레포지토리는 원격 저장소 우리의 경우는 깃허브를 말한다. 로컬PC의 영역까지는 와이파이가 없는 환경에서도 add, remote가 가능하고, 이제 리모트 레포지토리로는 와이파이가 되는 환경에서 한마디로 서버에다가 올리는것이다. 그리고 이제 이 서버에 접근을 할 수 있는 팀원들은 이 서버로부터 클론을 받아와서 각 로컬PC에 처음 만든 사람의 로컬PC에 저장된것과 똑같은것이 복제가 된다. 
- 처음 쉽게 설명된 개념으로 돌아가면, 작업 폴더에서 대기실로 add 라는것을 하고, 대기실에서 내 저장소로 commit이라는것을 하고, 내 저장소에서 원격 저장소로 push origin main이라는것을 하고 이걸 누군가 했다면, 다른 누군가는 이것을 받기 위해 pull origin main을 한다. 
- **git init** 원격 저장소에 올리기전에 먼저 되어져야할것은, 내가 만든 워킹 디렉토리를 먼저 깃 초기화를 해야한다. 그떄 쓰는 명령어다. 
- **git remote add origin 원격저장소링크** 이것은 이제 앞으로 로컬pc에서 커밋한것들을 push로 원격 저장소로 올리기전에 필요한 작업이다. 
- **git clone 원격저장소링크** 이것은 이제 같은 일을 하는 팀들의 경우, 팀장이 원격 저장소를 만들어 로컬pc와 연결시켜 push를 했다면, 팀원들은 그 원격 저장소 링크를 받아 클론으로 복제를 받아 각 로컬PC에도 팀장님과 같은 로컬저장소와 같은 세팅을 받을 수 있다. 

### Git 브랜치와 협업 
- 브랜치란? 본 줄기(main)를 그대로 두고 옆으로 갈래를 내서 작업하는 방법
- 모두가 다 main에 커밋을 하게 되면 반쯤 만든 기능도 main에 섞이고 누가 작업한건지 알기 힘들다
- 그래서 각자 새 브랜치에서 작업을 하고 그 다음에 main으로 합친다. 이러면 main은 늘 잘 돌아가는 상태로 남는다. 
- **git branch 새브랜치이름** 새로운 브랜치는 이렇게 만든다. 
- **git checkout 새브랜치이름** main에서 새로운 브랜치로 옮겨갈때 이렇게 쓴다. 반대로는 main이라고 쓰면 된다. 
- **git merge 브랜치이름** merge는 받는 쪽에서 한다. 받는쪽이란 먼저 checkout으로 가 있는 브랜치다. 가져올쪽은 git merge를 쓰고 뒤에 그 브랜치 이름을 쓰면된다. 

### Git diff로 확인 
- **Git diff**는 커밋하기 전에 뭘 고쳤는지 확인시켜준다. 두 모습을 나란히 놓고 지은 줄과 넣은 줄을 골라 보여준다. 
- 항상 두 칸을 비교한다. **git diff**로 워킹디렉토리(작업폴더)와 스테이징(대기실)을 비교해서 add 전에 고친 줄을 확인시켜주고, **git diff --staged**로 스테이징(대기실)과 로컬 레포(내 저장소)를 비교해서 commit 될 줄을 확인시켜주고, **git diff main 새브랜치명**로 main과 새 브랜치의 차이를 보여줘서 merge를 하기전에 미리 볼 수 있습니다.
