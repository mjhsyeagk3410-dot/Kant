# 오늘의 학습목표
```md
## 가상의 팀을 꾸린다
## 가상의 팀의 팀장님이 레포를 만든다
## 가상의 팀의 팀원들이 그 레포를 복제받는다
## 가상의 팀의 팀장과 팀원들이 푸쉬를 하면서 겪는 충돌을 경험 및 해결한다
```    

## 깃허브 레포 만드는 과정 
- 팀장이 로컬pc에서 프로젝트 디렉토리를 만든다.
- 만든 디렉토리에서 깃 초기화를 한다 
```sh
git init
``` 
- 해당 디렉토리에 README.md 파일을 만든다. 
```sh
touch README.md 
```
또는
```sh
echo "# tutorial" >> README.md
```
- 팀장이 깃허브에서 프로젝트 레포를 만든다. (리드미파일은 로컬에서 이미 만들었으니 만들지 않는다)
- 팀장은 vs code같은 곳에서 remote로 깃허브로 만든 프로젝트 레포를 연결시킨다. 
```sh
git remote add origin 레포링크주소
```
- 깃허브 프로젝트 레포에서 팀원들을 추가한다. (이메일을 공유받아 이메일로 추가한다)
- 그 팀원들은 이메일에 온 해당 프로젝트 레포를 열 수 있는 메일을 받는다 
- 각 팀원들은 메일을 확인하고 해당 프로젝트 레포를 열고 레포 링크를 복사하고, 각자 클론으로 복제받는다. 
- 이제 팀끼리 서로 각자 로컬pc에서 작업을 한 파일을 add, commit, push를 할 수 있고, 또 다른 누가 수정하면 pull을 할 수 있다. 

## 팀끼리 작업하다가 충돌이 일어날때해 해결하는 과정 
- A팀원이 echo.md 첫 줄을 "안녕하세용"이라고 적고 add, commit, push를 했다
- B팀원도 echo.md 첫 줄을 "안녕하세여" 라고 적고 add, commit을 하고 push를 하려고 한다.
- 그러면, B팀원이 push를 하려고 하니까, 먼저 pull을 하라는 내용이 뜬다. 다른 사람이 push를 했으니까.
- 그렇게, B팀원이 pull을 하니까, 같은 줄에서 같은 수정이 일어났는데, 그걸 무시하고 B가 만든걸로 바꾸겠냐 아니면 A가 올린대로 냅두겠냐라는 내용이 나타난다 (요약하면 충돌이 난다.)
- 그러면 B팀원은 A팀원과 소통을 해야할것이고, 의견조율을 해서 어떤 변경사항을 남길지를 정한 후, 그렇게 수정한다. 
- 그리고 B팀원은 현재 내 로컬pc에서의 상황을 일단 add, commit, push를 한다. 
- 이렇게 과정이 일단락된다.
