#### 17 설계원칙에서 시작한 책임분리 
- DIP, OCP 설계 원칙에 따른 변경에는 닫히고 확장에는 열린 구조 
- DIP, OCP는 객체지향 설계 5대 원칙 중 2가지인데
- DIP(Dependency Inversion Principle, 의존관계 역전 원칙)은 쉽게 말해 변하지 않는 핵심 비즈니스 로직(상위 모듈)이 자주 바뀌는 구체적인 구현체(하위 모듈, 예: 특정 DB드라이버, 외부 PG사 API등)에 직접 의존하면 안 된다는 뜻. 
- OCP(Open/Closed Principle, 개방-폐쇄 원칙)는 기존의 코드를 수정하지 않고도(Closed) 시스템의 기능을 새로운 요구사항에 맞게 확장(Open)할 수 있어야 한다는 뜻

#### 19 구조 변경 전 기존 기능을 보호하는 테스트

- 사용자가 실제로 서비스를 이용하는 가장 중요하고 필수적인 전체 흐름 몇 가지를 선정해 처음부터 끝까지 정상 작동하는지 검증하는 테스트를 뜻함
#### 20 TDD, 실패하는 테스트에서 시작하는 개발
- TDD(Test-Driven Development, 테스트 주도 개발)은 코드를 작성하기 전 테스트 케이스를 먼저 작성하고 그 테스트를 통과시키는 과정을 반복하며 소프트웨어를 구축하는 개발 방법론
- 구현보다 기대동작의 정의가 먼저인 red->green->refactor사이클
- Red: 실패하는 테스트 작성하기
- Green: 테스트를 통과시키기
- Refactor: 코드 개선하기

#### 21 실제 요청 흐름과 Controller 단위 테스트

#### 22 Mock와 Fake테스트 대역의 두가지 방식
